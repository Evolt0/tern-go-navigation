# Bug: macOS Go 导航耗尽文件描述符

## 现象与复现

大工作区中出现 `Go navigation failed: too many open files`。本机旧插件后台曾持有 9,995 个数字文件描述符，最高编号为 9,999；其中 8,448 个来自 Go 工具链和模块缓存。

使用项目锁定的 `fsnotify v1.9.0`，仅监听含 2,048 个无关 `.txt` 文件的目录即增加 2,055 个描述符。连续创建并关闭 12 次监听器仍残留 120 个描述符；12 次取消初始化残留 12 个。对应永久回归位于 `watch_darwin_test.go`，已验证旧后端失败。

## 根因

- macOS kqueue 后端会隐式打开监听目录内的文件，应用层 `relevantFile` 不能阻止该分配。依赖发现把标准库和依赖包目录纳入监听，大项目放大了占用。
- `fsnotify v1.9.0` 的 kqueue `Close` 先标记关闭，后续 `Remove` 因关闭状态直接返回，文件描述符未释放。失败后重新初始化也会保留旧句柄。
- 单纯切换 FSEvents 但逐包设置 `WatchRoot` 仍不够：系统会为监听根及祖先持有句柄，同一项目曾实测仍占 8,413 个。

## 修复

- `watch.go` 保留工作区、本地替换模块、依赖包发现与 LSP 动态注册；目录监听失败立即向调用方传播，不被 `go list` 的容错路径吞掉。
- `watch_darwin.go` 使用一个 FSEvents 流。原生路径合并为工作区根、实际 Go 工具链的 `GOROOT/src`、`GOMODCACHE` 及必要外部根；包级递归 / 非递归范围和忽略目录仍独立过滤，扩大原生根不扩大通知语义。
- 根配置批量应用，使用基线扫描前捕获的事件 ID 回放注册窗口内的事件。正常查询不重新扫描整个工作区；仅事件影响的目录需要成员重建。
- 每次同步在同一流的私有目录中写入唯一标记，等待其回调后 flush 并经过串行调度屏障。实测仅调用 `FSEventStreamFlushSync` 不能始终覆盖尚在内核中的即时修改，因此不能省略标记往返。
- 原生回调只持有整数 token；回调函数进程内复用，路径在跨越回调生命周期前复制，重复路径更新使用已拥有的字符串键。关闭按 stop、invalidate、回调屏障、release 和队列回收顺序执行，并删除私有控制目录。
- 事件丢失、历史不完整、根 / 挂载变化使会话失败，后续请求重建；不返回可能过期的导航结果。
- `fsevents_darwin.go` 通过 [purego](https://github.com/ebitengine/purego) 调用系统框架，保留 Go 1.23 与 `CGO_ENABLED=0`。其他现有 Unix 平台继续使用 `watch_fsnotify.go`。
- 发布包按实际二进制的依赖构建信息检查许可证，不再假定所有平台均编译 fsnotify。

## 验证

- `go test -race ./...` 通过，覆盖即时磁盘修改、原子保存、目录移入 / 删除、外部替换模块、外部工作区、模块配置变化及未保存缓冲区。
- 即时事件顺序相关的原子保存、目录移入、非递归范围、忽略目录与模块配置用例，在竞态检测下连续 10 轮通过。
- 新增描述符占用、重复关闭、取消初始化、gopls 启动失败回收、原生根合并与通知范围回归。
- `GOTOOLCHAIN=go1.23.12 CGO_ENABLED=0 go test -run '^TestWatcher' -count=1` 通过。
- 真实 CLI：12,000 个无关文件下后台为 33 个描述符，导航成功；原子保存后立即返回新的第 6 行定义。
- 原问题工作区：后台为 48 个描述符，项目符号查询返回实际 `config.go:20`。
- macOS amd64 发布包的校验和、许可证、未保存导航及项目符号查询冒烟通过。macOS arm64、Linux amd64 / arm64 已交叉构建，并验证归档、校验和、二进制格式及实际依赖许可证；这些目标未在本机执行。
- 已更新本机复制安装的插件后端并执行 `tern plugin reload go-navigation --json`，状态为 `ready`、无插件问题；旧泄漏后台在替换可执行文件后自行退出。对实际安装路径再次执行大文件数与原项目 CLI 冒烟，分别为 33 / 48 个描述符，结果正确。

## 升级与边界

复制安装需更新实际插件目录内的二进制；只构建另一个源码目录不会替换安装版。旧 kqueue 进程已经泄漏的句柄只能通过进程退出释放，升级时重新加载插件并重启 Tern 一次。无需修改系统文件描述符限制。不终止其他工具使用的 gopls 服务。
